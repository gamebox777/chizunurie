# 重要なローカルファイル（git管理外・要バックアップ）

このプロジェクトには、セキュリティ上の理由で **`.gitignore` され git に入っていない**が、
ビルド・デプロイ・本番運用に**必須**のファイルがある。リポジトリをクローンしただけでは
これらは手に入らないため、**別PC・新環境で作業する場合は手動でコピーする必要がある**。
紛失すると復旧が困難なものもあるので、安全な場所（1Password等のパスワードマネージャ・
暗号化ストレージ）にバックアップしておくこと。

> いずれも `.gitignore` 済み。`git status --ignored` で確認できる。
> **絶対に git にコミットしない**（公開リポジトリに鍵・パスワードが漏れる）。

---

## 一覧（重要度順）

| ファイル | 用途 | 紛失時の影響 | 再生成 |
|---|---|---|---|
| `mobile/android/upload-keystore.jks` | **Androidアプリ署名鍵** | Playへ更新を出せなくなる | リセット申請が必要（後述） |
| `mobile/android/keystore.properties` | 上記鍵のパス・パスワード | 署名できない | 鍵があれば再作成可 |
| `backend/.env` | バックエンドの本番/開発シークレット | 認証・DB接続不可 | 値が分かれば再作成可 |
| `.env`（ルート） | docker compose 用シークレット | DB起動・認証不可 | 値が分かれば再作成可 |
| `mobile/android/local.properties | Android SDK の場所 | Androidビルド不可 | **自動生成（コピー不要）** |
| `pmtiles`（ルート） | go-pmtiles バイナリ（地図変換） | PMTiles再生成不可 | 再ダウンロード可 |

## 1. Android 署名鍵（最重要）

### ファイル
- `mobile/android/upload-keystore.jks` … 署名鍵本体（バイナリ・約2KB）
- `mobile/android/keystore.properties` … 鍵の参照情報（**パスワード平文を含む**）
  ```
  storeFile=upload-keystore.jks   ← 相対パス。.jks と同じ階層に置くこと
  storePassword=********
  keyAlias=upload
  keyPassword=********
  ```

### なぜ git管理外でも必須か
Google Play は「同じ `applicationId`（`jp.chizunurie.app`）の更新は、**初回と同じ鍵で
署名されたものだけ**受け付ける」。別PCで新しく鍵を作って署名すると Play が別物とみなして
**更新を拒否**する。よって別PCでビルドするには、この2ファイルを**そのままコピー**する。

エイリアスが `upload` なので、これは **Play App Signing のアップロード鍵**。最悪紛失しても
Google にアップロード鍵リセットを申請すれば復旧できる（ただし審査待ち・手間が発生）。
それでも保持し続けるのが圧倒的に楽。**必ずバックアップすること。**

### 別PCでビルドする手順
1. 上記2ファイルを `mobile/android/` 直下に置く（**同じファイル名・同じ階層**）
2. `cd mobile && npm run bundle` で同じ署名のAAB（`app/build/outputs/bundle/release/app-release.aab`）ができる
   - `build.gradle` は `keystore.properties` が在るときだけ release 署名する（無いとデバッグ署名のまま＝Play に出せない）

### 渡し方の注意
`keystore.properties` はパスワード平文を含む。Slack/メール平文で送らず、暗号化zipや
パスワードマネージャ経由で渡す。

## 2. バックエンドのシークレット `backend/.env`

含むキー（値は秘匿）：
```
DATABASE_URL          PostgreSQL 接続文字列
BETTER_AUTH_SECRET    better-auth のセッション署名鍵（本番と一致させる）
BETTER_AUTH_URL       認証のベースURL
FRONTEND_URL          CORS 許可元
GOOGLE_CLIENT_ID      Google OAuth クライアントID
GOOGLE_CLIENT_SECRET  Google OAuth シークレット
```
- 雛形：`backend/.env.example` / `backend/.env.production.example`（git管理下）
- `GOOGLE_CLIENT_ID` / `SECRET` は Google Cloud Console から再取得可（`docs/GoogleOAuth設定手順.md` 参照）
- `BETTER_AUTH_SECRET` は**本番と同じ値**でないと既存セッションが無効化される。控えておくこと。

## 3. ルート `.env`（docker compose 用）

```
POSTGRES_PASSWORD     開発用 Postgres のパスワード
BETTER_AUTH_SECRET    （compose から backend へ渡す分）
```
- 雛形：`.env.example`（git管理下）

## 4. `mobile/android/local.properties`

`sdk.dir=...`（Android SDK の場所）だけ。**Android Studio が自動生成する**ので、別PCでは
コピー不要（環境ごとにパスが違う）。一覧には載せたが**バックアップ不要**。

## 5. `pmtiles`（ルートの go-pmtiles バイナリ）

`scripts/build-pmtiles.mjs` が使う Mach-O arm64 バイナリ（約55MB）。Mac/Linux 版は
https://github.com/protomaps/go-pmtiles/releases から取得してルートに `pmtiles` として
置く（Windows は同梱の `pmtiles.exe`）。**再ダウンロードで復旧できる**ので機密性は低いが、
PMTiles を再生成するなら必要。

## iOS について

現状 iOS の署名は Xcode／Apple Developer アカウント側で管理しており、リポジトリ内に
git管理外の秘密ファイル（`.p12` / `.mobileprovision` 等）は**置いていない**。iOS でビルド・
配布する場合は Apple Developer の証明書・プロビジョニングプロファイルを各PCの Xcode で
設定する（`mobile/README.md` 参照）。将来 fastlane 等でローカルに証明書ファイルを置く運用に
したら、ここに追記すること。

---

## バックアップ運用メモ

- 最低限 **`upload-keystore.jks` + `keystore.properties` + 各 `.env`** を暗号化して退避。
- パスワード（keystore の store/key、DBパスワード、AUTH_SECRET）は別途パスワードマネージャに記録。
- これらは**絶対に git にコミットしない**（`.gitignore` 済みだが、`git add -f` 等で誤って入れない）。
